# Schema Recommendation: Adding Region

I would choose the normalized approach by creating a separate regions table and adding a region_id column to the listeners table. Since the plays table receives a new row every time a song is played, storing region information in every play would create unnecessary duplication and increase storage costs. Although normalization introduces additional joins when generating regional reports, properly indexed columns can help reduce the cost of those joins. This approach also avoids maintaining a large region-based index across millions of play records. Report A demonstrated how a composite index can help PostgreSQL efficiently locate relevant records without scanning the entire table. Assuming the report is based on each listener's current region, normalization provides a good balance between performance, storage, and maintainability.
